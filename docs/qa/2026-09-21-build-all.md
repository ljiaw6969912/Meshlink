## 实际报错后的布局并发修复

用户再次运行入口时，全量测试中的桌面包出现 `panic: send on closed channel`。
原始日志定位到 Walk 的 `layout.go:276`：窗口销毁会关闭协调协程的结果通道，
但异步布局线程可能刚完成计算，仍在向该通道发送。流程因此在测试阶段停止，
尚未覆盖发布目录。直接重跑偶尔成功，不能证明该竞争已消失。

将当前 Walk 版本的构建源码固定在 `third_party/walk`，通过 `go.mod` 的
replace 统一用于普通构建和发布。上游代码只改两处：协调协程退出时不关闭
工作线程仍持有的私有结果通道；结果发送同时监听取消，防止接收者退出后阻塞。
其余复制源码经 SHA256 比对与原版本一致，原许可证保留并加入随包声明。

- `go test github.com/lxn/walk -run '^TestLayoutTreeCancellationDuringResultDelivery$' -count=1`：原实现稳定失败，报告取消后布局线程未退出。
- 相同测试在修复后 `-count=100` 通过；使用 synctest 调度同步，不靠延时碰运气。
- `go test ./cmd/mesh-desktop -count=3 -timeout=120s`：通过，耗时 24.985 秒，包含 150 次真实隐藏窗口布局后销毁。
- 一键流程隔离测试通过，并验证正式测试阶段包含 Walk 依赖回归。
- 两个 Windows 构建脚本均执行 Walk 回归，不跳过原有 Meshlink 全量测试。
