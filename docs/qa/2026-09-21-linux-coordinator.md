# Linux 命令行服务器验证

## 本次行为

- `cmd/mesh-coordinator` 单进程运行协调服务与本机组网节点，不提供 GUI。
- 首次启动指定公网地址，自动初始化网络、生成长期接入链接和六位验证码；正常重启复用身份、IP、接入信息、监听地址。
- 本机节点地址为 `10.77.0.1`；Linux 通过 TUN 与其他节点直连，需 `iproute2` 与网络管理权限。
- 数据目录使用操作系统文件锁，阻止第二个实例同时改写同一网络；锁随进程退出释放。
- 可通过 `-new-code` 换码、`-max-uses` 调整接入次数，`-devices` 输出设备 JSON。终端支持 SIGTERM/Ctrl+C，附带 systemd 示例。
- 保留已有显示名称；自定义证书路径不由简化启动器覆盖，明确报错并保留原配置。

## 验证记录

- Go 测试覆盖首次创建本机节点、重启时 CA/NodeID/IP/接入信息保留、显式换码、错误参数拒绝、数据目录互斥和自定义证书配置保留。
- Linux amd64/arm64 使用 `CGO_ENABLED=0` 编译；核对 ELF 架构、程序 0755 权限、七项归档白名单、元数据 SHA-256，包内没有运行配置和私钥。
- WSL 中运行 Linux ELF 的 `-version`、`-help` 成功；缺少 TUN/iproute2 时的启动前检查正确失败，未创建网络身份。
- 使用隔离测试数据和空设备的 Linux 协调进程，Windows 测试客户端经真实 TLS 成功登记为 `10.77.0.2`，Linux 本机节点为 `10.77.0.1`；重启验证身份、证书和接入信息保留。
- Linux 控制连接的证书边界测试、UDP 协调探测及重放拒绝测试通过。
- Windows 主机最终 `go test ./...` 与 `go vet ./...` 通过。一次并发构建期间的旧直连撤销测试出现超时，随后该用例连续三次通过，最终全量重跑通过。

## 当前实机验证限制

本机 Linux 环境为 WSL1，没有真正的 TUN 支持。该环境的 `IP_TOS` 辅助数据长度返回 4 字节，quic-go Linux 路径期待 1 字节，导致 `invalid IPTOS size`；关闭 GSO/ECN 并未改变该错误。该错误已通过独立 UDP 控制消息探针复现，不将其隐去或算作生产二进制直连成功。

仅测试的 PacketConn 适配器隐藏 WSL1 不兼容的辅助数据后，服务器作为发起方和接受方的真实 QUIC 双向传输均通过。该测试使用空设备，不修改发布代码，也不能替代原包的 Linux TUN 实机验证。

尚未在真实 Linux 内核主机验证 TUN 创建、网卡路由与实际远程桌面/SSH 数据传输，也未实际安装启动 systemd 示例。交付包需在具备 TUN 的 Linux 主机进行最终网络联调。
