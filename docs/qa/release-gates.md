# Meshlink 产品改造发布门禁

本文档是 Meshlink 产品改造 Task 0 的发布基线。五个阶段与 `PRODUCT_TRANSFORMATION_PLAN.zh-CN.md` 第 13 章和总实施计划保持一致：自托管闭环、自建中继、官方 Hub MVP、P2P 直连优先、团队和商业化能力。

每个阶段发布前必须完成自动化测试、手工 E2E、构建/打包、合规/风控和回滚条件检查。任何阶段都不能削弱既有自托管服务器/客户端模式，不能引入匿名代理、公网出口、全局代理或长期匿名中继能力。

## 全局门禁

| 类别 | 全阶段要求 |
| --- | --- |
| 自动化测试 | 至少运行 `go test ./...`；涉及桌面、安装包、更新、Relay、Hub 或 P2P 的阶段还要运行对应包测试和场景测试。 |
| 手工 E2E | 每阶段至少执行该阶段的核心网络拓扑，并保留环境、步骤、预期结果、实际结果和失败采集项。 |
| 构建/打包 | 至少运行 `powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1`；发布候选版本还要运行 `powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Package` 并校验 `manifest.json` 与 zip 包版本一致。 |
| 合规/风控 | 每阶段都检查默认拒绝 `0.0.0.0/0`、`::/0`、公网出口、任意公网端口转发、匿名节点池、公开转发入口和无账号无设备绑定中继。 |
| 回滚 | 发布前必须记录上一稳定版本、升级路径、配置兼容性、证书兼容性、状态文件兼容性和恢复步骤。 |

## 阶段一：自托管闭环

**关联 Task:** Task 1, Task 2, Task 8, Task 11

| 门禁类别 | 通过标准 | 失败标准 |
| --- | --- | --- |
| 自动化测试 | `go test ./...` 通过；`go test ./internal/config ./internal/onboarding ./internal/agent ./internal/ui ./internal/diagnose ./internal/update` 通过；新增或调整的桌面入口、onboarding、诊断和配置校验有对应测试。 | 任一测试失败；配置校验允许全隧道路由；错误信息只暴露底层异常且无处理建议。 |
| 手工 E2E | 两台 Windows 设备或两个隔离运行目录完成“创建服务器 -> 生成接入链接和接入码 -> 加入网络 -> 节点列表显示 -> 点击 RDP”；普通主流程不要求编辑 JSON、证书路径或服务名。 | 5 分钟内无法完成首次 RDP；节点列表无法反映在线/离线；RDP 不可达时没有用户可理解诊断。 |
| 构建/打包 | `powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1` 通过；发布候选版本执行 `-Package`，确认 `bin` 可执行文件、`dist\meshlink.zip`、`release\manifest.json` 和 `release\meshlink-版本号.zip` 生成正确。 | 构建失败；打包缺少核心二进制；manifest 版本与 zip 文件名版本不一致；构建过程覆盖真实配置、证书或日志。 |
| 合规/风控 | 默认用途表达为私有远程桌面组网；高级设置收纳但保留；设备禁用、拒绝列表、审计和路由安全校验按 Task 2 门禁进入。 | 首屏或发布说明把产品描述为匿名代理、通用 VPN、公网出口或规避监管工具；配置可接受全隧道路由。 |
| 回滚条件 | 升级失败可恢复上一稳定 `bin`；真实配置、证书、邀请、设备 registry 和日志不被覆盖；服务启动失败时可回退服务文件和可执行文件。 | 升级后证书或配置丢失；服务无法恢复；客户端无法识别上一版本更新包。 |

## 阶段二：自建中继

**关联 Task:** Task 3, Task 8, Task 11

| 门禁类别 | 通过标准 | 失败标准 |
| --- | --- | --- |
| 自动化测试 | `go test ./...` 通过；`go test ./internal/deployssh ./internal/onboarding ./internal/ui` 通过；SSH 认证失败、主机指纹变化、端口占用、权限不足、磁盘只读和二进制缺失均有测试或可重复模拟。 | SSH 失败后仍创建远程目录；主机指纹变化未阻断；部署错误只显示底层异常。 |
| 手工 E2E | 一台 Linux 云主机和两台无公网 Windows 设备完成 SSH 自动部署公网 Hub；本机和远端设备都能加入并远程桌面；远程健康检查能定位服务状态。 | systemd 服务未运行；第二台设备无法加入；部署失败没有明确失败点和下一步处理建议。 |
| 构建/打包 | Windows 与 Linux 目标产物可生成；部署向导上传的二进制、配置、证书和服务文件与发布包版本一致；发布候选版本执行 `-Package` 并验证自建中继安装包内容。 | 上传版本与本地版本不一致；缺少 Linux agent；升级包无法被远程服务启动。 |
| 合规/风控 | 自建中继仍是用户自控 Hub，不作为公开转发节点；部署向导不默认开放公网出口或任意端口转发；远程操作写入审计日志。 | 向导默认生成全局代理或公开转发配置；审计日志包含私钥或敏感凭据。 |
| 回滚条件 | 部署失败时自动回滚已上传服务或保留诊断包；升级失败可恢复上一版本远程目录和 systemd 服务；回滚后客户端连接恢复。 | 服务启动失败后留在半安装状态；回滚后配置、证书或接入链接失效。 |

## 阶段三：官方 Hub MVP

**关联 Task:** Task 4, Task 5, Task 8, Task 9, Task 11

| 门禁类别 | 通过标准 | 失败标准 |
| --- | --- | --- |
| 自动化测试 | `go test ./...` 通过；`go test ./internal/cloudhub ./internal/relay ./internal/policy ./internal/ui` 通过；账号、网络、设备、邀请、在线状态、Relay、限速、额度、封禁和吊销均有 API 或单元测试。 | 设备吊销后仍可连接；Relay 可访问公网 IP；错误验证码未触发限制；额度超限仍可新建 Relay 会话。 |
| 手工 E2E | 两台不同 NAT 网络下的 Windows 设备登录官方账号，创建官方网络，加入设备，通过基础 Relay 完成 RDP；后台能查看账号、设备、连接元数据和中继流量；封禁账号后设备在 1 分钟内断开。 | 无公网环境无法完成 RDP；后台无法定位连接对象；封禁或吊销不生效；普通流程要求用户理解 NAT 或证书。 |
| 构建/打包 | 客户端、`mesh-cloudhub`、`mesh-relay` 和运维配置可从干净 checkout 构建；发布候选版本包含服务端版本、客户端版本、数据库迁移说明和回滚包。 | 服务端或客户端无法构建；缺少迁移回滚说明；客户端与 Hub API 版本不兼容且无阻断提示。 |
| 合规/风控 | 可接受使用政策、隐私政策草案、用户协议草案、日志留存策略和投诉封禁流程完成内部评审；官方 Hub 不主动查看用户内容，只记录必要元数据；新账号低额度策略生效。 | 长期匿名中继可用；日志包含远程桌面内容、文件内容或剪贴板内容；商业外放前缺少律师审核记录。 |
| 回滚条件 | Hub 服务、Relay 服务、数据库迁移和客户端协议均有上一版本兼容方案；封禁、吊销和额度数据回滚不破坏账号安全；客户端可回退到上一稳定版本并识别服务端兼容状态。 | 数据迁移不可逆且无备份；回滚后设备凭据失效；旧客户端被静默接入不兼容 API。 |

## 阶段四：P2P 直连优先

**关联 Task:** Task 6, Task 7, Task 8, Task 11

| 门禁类别 | 通过标准 | 失败标准 |
| --- | --- | --- |
| 自动化测试 | `go test ./...` 通过；`go test ./internal/p2p ./internal/agent ./internal/cloudhub ./internal/relay ./internal/diagnose` 通过；候选地址去重、IPv4-only 校验、路径状态机、LAN direct、公网 direct、Relay fallback、NAT 探测和质量评分均有测试。 | 状态机无限重试；direct 失败不回 Relay；旧 `tcp_tls_v1` 连接被破坏；IPv6 被误接入当前 IPv4-only 流程。 |
| 手工 E2E | 同 LAN 两台设备显示 `lan_direct`；公网地址或端口映射设备显示 `public_direct`；阻断直连端口后 15 秒内回 Relay；客户端展示直连/中继/失败诊断。 | direct 场景 Relay 字节计数增加；阻断直连后 RDP 中断且不回退；用户看不到当前连接方式。 |
| 构建/打包 | P2P 新协议、旧 TCP/TLS 协议和 Relay 兜底同时进入构建；发布候选包包含协议版本兼容说明、网络实验室结果和回滚包。 | 构建缺少旧协议路径；新客户端无法连接旧自托管 Hub；包内缺少 P2P 诊断资源。 |
| 合规/风控 | P2P 只用于同一授权网络内设备连接；Hub 仍校验身份、权限、在线状态和设备吊销；Relay 令牌有过期和额度限制；打洞或 QUIC 选型完成安全和许可证审查。 | 无权限设备可获得候选地址；被吊销设备仍可直连；新传输绕过审计、封禁或额度策略。 |
| 回滚条件 | 可通过配置或服务端策略关闭新 P2P 路径并强制回到 Relay 或旧 TCP/TLS 路径；状态文件新增字段保持向后兼容；旧客户端可忽略新字段。 | 开关关闭后仍尝试 P2P；旧客户端解析状态文件失败；回滚导致已保存网络不可连接。 |

## 阶段五：团队和商业化能力

**关联 Task:** Task 9, Task 10, Task 11

| 门禁类别 | 通过标准 | 失败标准 |
| --- | --- | --- |
| 自动化测试 | `go test ./...` 通过；`go test ./internal/cloudhub ./internal/relay ./internal/policy` 覆盖套餐、额度、支付 provider、组织成员、RBAC、设备分组、审计查询、批量部署和私有化授权。 | 普通成员可执行管理员操作；支付回调重放重复加额度；超出日志保留期仍返回数据。 |
| 手工 E2E | 团队管理员创建组织、邀请成员、分配角色、分组设备、授权连接、查看审计；10 台测试设备批量部署后自动绑定组织；企业私有化部署在隔离网络可运行。 | 无权限成员可连接受限设备；审计缺少成员、设备、时间或连接方式；批量部署失败后无法单独重试。 |
| 构建/打包 | 团队版、企业私有化部署包、预配置安装包、离线更新和授权文件可构建并校验；发布说明区分免费、自建、官方 Hub、团队和企业能力。 | 授权文件无法校验；私有化包缺少离线更新路径；发布说明混淆免费能力和付费限制。 |
| 合规/风控 | 套餐额度、日志保留、团队审计、企业合同、技术支持 SLA、隐私政策和可接受使用政策保持一致；客服排查不查看用户内容。 | 付费限制被伪装成网络错误；客服流程需要查看远程桌面内容；企业授权过期策略与合同不一致。 |
| 回滚条件 | 套餐、额度、组织、RBAC 和授权文件变更有数据备份和迁移回滚；授权过期或回滚不破坏已有合同策略；客户端能清晰提示订阅状态。 | 回滚后团队权限扩大；额度数据丢失；授权过期导致合同内已有设备被意外断开。 |

## 发布判定

- 通过：对应阶段所有门禁类别均达到通过标准，且没有未解释的高风险项。
- 暂缓：自动化测试、手工 E2E、构建/打包、合规/风控或回滚条件中任一项未达标。
- 回滚：发布后出现数据丢失、证书或配置损坏、安全边界失效、官方 Hub 被用作公网出口、无法恢复远程桌面主流程、或错误率超过该阶段运维阈值时，立即执行回滚方案。
