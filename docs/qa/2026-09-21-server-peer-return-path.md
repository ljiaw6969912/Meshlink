# 0.1.9 服务器本机节点回包路径验证

## 问题与变更

服务器自动运行的本机节点与普通客户端使用相同的虚拟网卡、双向认证 QUIC 和设备列表。现场出现控制连接正常、UDP 探测能到达、服务器与客户端却反复停留在 `punching` 的情况。服务器有多张网卡，入站控制连接使用以太网，而返回客户端公网地址的默认路由选择了代理虚拟网卡。

Windows 上 quic-go 0.61.0 使用 `ReadFrom` / `WriteTo` 读写 UDP，没有保存入站报文的本地目标地址和接口。现为候选服务的同一个 UDP socket 启用 `IP_PKTINFO`，通过 `ReadMsgUDP` 记录实际收包路径，通过 `WriteMsgUDP` 指定回复的源地址和接口；无需改变操作系统路由或代理设置。首次向未知端点发送仍使用正常路由。

回包信息按远端 IPv4 和端口区分，最多保留 4096 条，2 分钟过期，收到新包会更新路径。缓存仅决定本地出口，证书、节点身份、远端候选匹配和一次性会话密钥校验保持不变。非 Windows 平台继续使用 quic-go 原有实现。

兼容 Go 1.26 Windows 的 `WSASendMsg` 同步成功返回零字节计数的情况：成功发送 UDP 整包时返回实际数据长度，避免打洞代码把已发送数据误判为短写。

参考：[Microsoft IN_PKTINFO 定义](https://learn.microsoft.com/en-us/windows/win32/api/ws2ipdef/ns-ws2ipdef-in_pktinfo)。
