# 2026-09-17 连接问题修复测试包

本文保留当时的排查记录，不作为当前操作说明。0.1.6 已统一为一个“连接”按钮，服务器本机也加入组网；当前发布流程见 `simple-mesh-release-20260920.zh-CN.md`。

## 本次修复

- A 是协调服务器，没有上游连接，不能因此把已接入的 B 显示为离线。管理界面现在分别显示服务器运行状态、节点在线状态和直连路径状态。
- 启动现有服务器时复用并验证已有 CA，不再重建信任根。证书损坏或丢失时明确报错，不静默创建替代身份。
- Windows 包必须包含 bin/wintun.dll，缺失时打包和验包均失败。

## 升级和本轮恢复

1. 不删除或覆盖现有 configs、certs、invites 及设备记录；不要把 A 的证书或私钥复制给 B/C。
2. A 的服务和 B 的现有连接无需为界面修复而重启。A 当前运行目录的 bin 下提供 mesh-desktop-connection-fix.exe，可退出旧管理窗口后运行此文件。不要在旧窗口再次点击“启动服务器”。
3. A 本轮旧邀请码已使用 3/3 次。请在修正版管理窗口点击“重新生成接入码”，使用新链接和验证码。
4. C 的日志显示 TLS 证书验证失败。重新连接只会使用本地旧证书，不能更新信任。请使用新测试包，在 C 上填写新链接和验证码，以独立名称（例如 C-LJW）点击一次“加入网络”。后续只用“重新连接”，不要反复注册同名节点。
5. 新包为未签名开发测试包。C 上应从新包 bin 目录以管理员权限运行 mesh-desktop.exe，完整保留同目录的 mesh-agent.exe 和 wintun.dll。

## 验收边界

- 自动测试覆盖：服务器重启后原 CA 和私钥保持不变；原客户端信任仍可验证新服务器证书；CA 私钥缺失或两份 CA 文件都缺失时不重建网络；A 的在线成员不会因无上游连接而被标为离线。
- 包含全量 Go 测试、Windows/Linux 构建、发布脚本测试、文件清单/哈希校验、重复打包一致性检查。
- 自动测试通过不代表 B/C 现场联调已经通过。C 接入后仍需核对 A 上同时出现 B/C 在线，再实际建立 B↔C 直连；只有在该路径确已建立后，才能进行停 A 不断流的验收。
- 本包不自动清理历史重复注册记录，也不会绕过 TLS 校验。
