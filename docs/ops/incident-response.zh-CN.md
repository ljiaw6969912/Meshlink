# 事故响应与客服排查手册

本文用于 Meshlink 客服和运维在不接触用户内容的情况下，按 account ID、device ID 和 UTC 时间范围，把登录失败、设备入网失败、连接协商/网络路径失败、Relay 异常和目标机 RDP 不可达定位到固定层级。配套本地工具为 [`scripts/support-triage.ps1`](../../scripts/support-triage.ps1)。

本文不是工单平台、远程控制工具、内容查看流程或监控平台设计，也不授权客服绕过现有 RBAC、账号状态、套餐额度、组织隔离、安全审批或数据保留策略。

## 1. 不可突破的边界

- 只使用账号/设备标识、包含边界的 UTC 时间范围、受控状态、路径类型、受控错误码、Relay 状态和现有诊断 finding code 等最小元数据。
- 不得索取、采集、复制或查看屏幕/远程桌面画面、文件、文件名清单、剪贴板、键盘输入、密码、一次性验证码、token、私钥、候选/远端地址、原始流量或任意自由文本日志。
- 不得让用户把完整配置、`internal/diagnose` 的 `checks/detail`、抓包或凭据粘贴进工单或排查脚本；现有诊断只向脚本提供 `finding.code`、`severity` 和时间。
- 脚本不查询 API、不联网、不上传、不发遥测、不更改账号/设备/网络/RDP 状态；默认只在当前目录生成一个新的脱敏 JSON 文件。
- 客服不得远程控制目标机。需要在目标 Windows 上启用 RDP、调整防火墙或重启服务时，由用户或其授权管理员本地执行。
- 出现安全停止条件时，不再继续普通排查，立即转入安全事件响应。

## 2. 角色、职责与交接

| 角色 | 可以做什么 | 不可以做什么 | 交接点 |
| --- | --- | --- | --- |
| L1 客服 | 核验工单主体；收集 account ID、device ID、UTC 时间范围；运行本地聚合脚本；按本文给出用户可执行步骤 | 查询无授权组织、查看内容、索取凭据、改额度、远程控制、执行生产回滚 | 完整跑一遍固定顺序仍为 `unknown`，或 30 分钟未定位时交 L2 |
| L2 支持/运维 | 在现有 RBAC 授权下查询最小审计/连接元数据；核对多工单是否同一故障；协调服务负责人 | 扩大字段、导出原始日志/流量、绕过 owner/admin 权限、擅自改账号或生产配置 | 60 分钟仍未定位、同一签名出现 3 个及以上独立工单、需要生产变更/回滚时交服务负责人和事故指挥 |
| 账号/套餐负责人 | 核验冻结、封禁、membership、套餐和额度；执行已有受控恢复流程 | 通过临时改数据绕过正式额度或审计 | 账号恢复后把受控结果码和时间交回 L2 |
| 网络/Relay/RDP 负责人 | 分别处理服务路径、Relay 健康和目标机 RDP 配置；提供受控状态码 | 向客服索取内容、候选地址或抓包 | 缓解完成后把恢复时间、受影响层和验证结果交事故指挥/L2 |
| 事故指挥 | 确认级别、范围、更新节奏、缓解/恢复、回滚和结束条件 | 在证据不足时宣称根因或恢复 | P0/P1 立即接管；P2 多用户事件由 L2 请求接管 |
| 安全负责人 | 接管疑似入侵、凭据泄露、越权、跨组织访问或内容暴露 | 让普通客服继续试探性查询 | 任何安全停止条件触发时立即接管 |
| 隐私/数据负责人 | 批准例外保留、legal hold 和删除证明 | 用例外保留替代正式审批 | 需要超过本文默认期限或发生内容/凭据误采集时介入 |
| 客户沟通负责人 | 发送已确认的影响、缓解、下一次更新时间和恢复说明 | 暴露内部 ID、地址、token、个人信息或未确认根因 | P0/P1 由事故指挥指定；P2/P3 默认由工单 owner 承担 |

客服身份不等于组织 owner/admin。组织审计仍只能由现有授权角色查询；无授权时交给对应组织的受控查询人员，不能借排障理由扩大权限。

## 3. 固定分级与事件分类

### 3.1 严重级别

| 级别 | 固定判定 | 首次响应 | 更新节奏 |
| --- | --- | --- | --- |
| P0 | 已确认跨组织越权、用户内容/凭据暴露、正在进行的入侵，或需要立即阻断的安全事件 | 立即停止普通排查并通知安全负责人和事故指挥 | 由安全事件流程决定 |
| P1 | 疑似安全事件；大范围登录/控制面/Relay 不可用；多数用户无可用路径 | 15 分钟内事故指挥接管 | 每 30 分钟，或状态改变时 |
| P2 | 多用户或单一区域持续降级，有替代路径但明显影响使用 | 30 分钟内由 L2 评估是否启动事故 | 每 2 小时，或状态改变时 |
| P3 | 单账号、单设备、单路径、单目标机 RDP 问题 | 正常工单时限 | 每个关键交接/状态改变时，至少每个工作日一次 |
| P4 | 咨询、无法复现且没有失败证据、恢复后观察 | 正常工单时限 | 关闭前一次 |

`support-triage.ps1` 只依据单工单输入输出 P1（安全）或 P3/P4。工单数量、区域范围和服务影响需要事故指挥按上表人工提升，脚本不会自动推断全局事故。

### 3.2 必须区分的类别

| 类别 | 典型证据 | 不应误判为 | 负责人 |
| --- | --- | --- | --- |
| `security_event` | 越权、凭据/内容暴露、异常访问受控状态为 suspected/confirmed | 普通登录或网络失败 | 安全负责人 |
| `service_outage` | 多个独立账号/设备在同一时间窗口、同一服务层同时失败 | 单机 RDP 未启用 | 事故指挥与服务负责人 |
| `account_or_quota` | 冻结/封禁/停用、membership 无效、`quota_exceeded` | 防火墙或 Relay 故障 | 账号/套餐负责人 |
| `login` | 账号有效但受控登录结果为 failed | 设备离线 | 账号/认证负责人 |
| `enrollment` | 登录成功但设备入网结果为 failed | 连接协商失败 | 设备入网负责人 |
| `network_path` | 设备/agent/虚拟网卡离线，协商 failed/closed/offline，或 `network_blocked` | RDP 服务未启用 | 网络负责人 |
| `relay` | direct 不可用且 Relay failed/degraded，或 `relay_path_anomaly` | 套餐 Relay 额度不足；后者属于账号/额度 | Relay 负责人 |
| `target_rdp` | 账号、入网和网络路径均正常，但 RDP disabled/stopped/blocked/unreachable | Meshlink/Relay 故障 | 目标机管理员/RDP 负责人 |

## 4. 受理与最小证据

### 4.1 工单必须字段

1. 已完成工单主体和组织归属核验；记录核验方式，不记录凭据。
2. 完整 account ID 和 device ID 只进入有访问控制的工单/查询入口。脚本输出只保留 `sha256:` 开头的 16 位十六进制短引用。
3. `from_utc`、`to_utc` 使用 RFC 3339 UTC（以 `Z` 结尾），两端均包含；优先收窄到故障前后 5 至 15 分钟。
4. 用户可见现象只使用受控选项，例如“登录失败”“设备不在线”“连接失败”“连接经 Relay 但降级”“RDP 不可达”；不要收集画面或自由文本内容。
5. 记录问题是否仍在发生、单用户还是多用户、首次/最近发生时间和用户已本地执行的非敏感步骤。

### 4.2 允许查询/聚合的证据

- 账号/套餐：`ok`、`locked`、`disabled`、`quota_exceeded`、`unknown`，以及受控 reason code。
- 登录：成功/失败/未知、时间、受控 reason code。
- 入网：成功/失败/未知、时间、受控 reason code。
- 连接：connected/failed/offline、direct/relay、connected/failed/closed/offline/rdp_unreachable/fallback_relay、时间、受控 error code。
- Relay：ok/degraded/failed/not_used/unknown、时间、受控 error code。Relay 配额不足仍归入账号/额度，不伪装成网络错误。
- RDP：reachable/unreachable、是否启用、服务 running/stopped、特定 RDP 防火墙规则 allowed/blocked、时间、受控 error code。
- 现有一键诊断：只取 `findings[].code`、`severity`、时间；不取 `checks[].detail`。

查询结果若因套餐/组织审计保留期被截断，必须在工单记为“证据受保留期限制”，不能把空结果解释为“当时没有事件”，也不能复制数据来旁路现有保留策略。

## 5. 固定诊断顺序

每次都从第 0 步开始。上层未通过时停止向下猜测；修复后从第 0 步重跑一次。

0. **安全与授权**：确认查询人、组织范围、工单目的。若 security 为 suspected/confirmed，或出现第 10 节任一停止条件，停止并升级安全响应。
1. **账号/额度**：检查 locked/disabled/quota_exceeded、组织/membership 和适用套餐。账号/额度失败时先处理此层。
2. **登录**：账号有效后检查时间窗口内登录结果和受控错误码。不得索取密码、token 或验证码。
3. **设备入网**：登录成功后确认目标 device ID 已入网且归属正确。跨组织或归属不明立即停止并升级授权/安全核查。
4. **agent 与连接协商**：确认两端 agent/虚拟网卡受控状态、设备 online/offline、path state。failed/closed/offline 归 `network_path`。
5. **路径类型**：只看 direct/relay 和受控状态，不看候选/远端地址。direct 正常则继续 RDP；direct 失败且进入 Relay 时继续第 6 步。
6. **Relay**：区分健康 Relay、Relay 降级/失败、Relay 配额不足。配额属于 `account_or_quota`；Relay 自身状态异常属于 `relay`。
7. **目标机 RDP**：仅当前六层都通过后检查 RDP 是否启用、服务是否运行、专用防火墙规则是否允许、端口诊断 finding 是否为 `rdp_unavailable`。

出现相互矛盾的证据时不选“最像”的根因：标记 `unknown`，保留查询范围和受控码，交 L2/对应服务负责人复核。

## 6. 本地支持排查脚本

### 6.1 输入格式

脚本接受 `meshlink.support-triage-input.v1`。以下示例全部是虚构标识和本地 fake 状态：

```json
{
  "schema_version": "meshlink.support-triage-input.v1",
  "case": {
    "account_id": "fake-account-001",
    "device_id": "fake-device-009",
    "from_utc": "2026-07-15T01:00:00Z",
    "to_utc": "2026-07-15T01:15:00Z"
  },
  "security": { "status": "clear", "observed_at_utc": "2026-07-15T01:01:00Z" },
  "account": { "status": "ok", "observed_at_utc": "2026-07-15T01:02:00Z" },
  "login": { "status": "ok", "observed_at_utc": "2026-07-15T01:03:00Z" },
  "enrollment": { "status": "ok", "observed_at_utc": "2026-07-15T01:04:00Z" },
  "connection": {
    "status": "connected",
    "path_type": "lan_direct",
    "path_state": "lan_direct_connected",
    "observed_at_utc": "2026-07-15T01:05:00Z"
  },
  "relay": { "status": "not_used", "observed_at_utc": "2026-07-15T01:05:00Z" },
  "rdp": {
    "status": "unreachable",
    "enabled": false,
    "service_state": "stopped",
    "firewall_status": "unknown",
    "observed_at_utc": "2026-07-15T01:06:00Z"
  },
  "diagnostic_findings": [
    { "code": "rdp_unavailable", "severity": "fail", "observed_at_utc": "2026-07-15T01:06:00Z" }
  ]
}
```

允许的顶层字段只有示例中的十项。任何额外字段都会整单拒绝，尤其不要提供 `checks`、`detail`、screen/file/clipboard、password/token/private key、candidate/remote address 或 raw traffic。输入文件上限 1 MiB；reason/error/finding 只能是最长 64 字符的结构化 code，不能放自由文本。

### 6.2 运行

```powershell
# 默认在当前目录创建唯一文件，不覆盖已有文件
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\support-triage.ps1 `
  -InputPath .\support-input.json

# 或显式指定新的本地输出文件
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\support-triage.ps1 `
  -InputPath .\support-input.json `
  -OutputPath .\support-report.json
```

脚本只向标准输出打印本地报告完整路径。`OutputPath` 的父目录必须已存在，且脚本拒绝覆盖已有文件。错误输入不生成报告。

### 6.3 输出解释

输出 schema 固定为 `meshlink.support-triage-report.v1`：

- `case.account_ref`、`device_ref` 是原 ID 的 SHA-256 前 16 个十六进制字符，仅用于同一受控排障上下文内关联。短摘要是伪名化而非匿名化，不得公开传播。
- `privacy` 明确声明本地输出、未发遥测、未收集用户内容/凭据。
- `classification` 给出 category、layer、P1/P3/P4、受控 code、摘要和是否必须停止并升级安全。
- `evidence` 只含每层状态、时间、受控 code，以及 connection 的 path type/state、RDP 的布尔/枚举状态。
- `actions` 是下一步，不是自动执行命令。

脚本输出是“根据已提供元数据得到的最早失败层”，不能替代授权查询、全局影响判断或真实设备验证。字段为 `unknown` 时应补齐允许的元数据或按交接阈值升级，不能索取内容来填空。

## 7. 沟通、缓解与恢复

### 7.1 每次更新固定五项

1. 已确认影响：账号/设备数量、时间范围和失败层；不写完整内部 ID。
2. 当前级别和类别；若未确认根因，明确写“定位中”。
3. 已做的只读核验和已授权缓解；不附原始日志/内容。
4. 用户当前可做的安全步骤或替代路径。
5. 下一次更新时间和负责人。

不要把“Relay 被使用”描述为故障；不要把 `quota_exceeded` 描述为网络问题；不要在只看到 `rdp_unavailable` 时宣称 Meshlink 服务宕机。

### 7.2 分类别缓解

- **安全事件**：普通客服停止；安全负责人决定隔离、冻结、吊销、保全和通知。未经批准不删除证据、不重置凭据、不扩大查询。
- **服务故障**：事故指挥冻结相关变更，服务负责人使用现有服务 runbook 处理。若最近变更与时间/范围吻合，只能由变更 owner 按既有发布/回滚流程回滚；客服不执行生产回滚。
- **账号/额度**：授权负责人修复账号/membership/套餐或正式调整额度。禁止临时绕过额度、伪造状态或把失败改写为网络错误。
- **网络路径**：由用户/管理员确认设备开机、agent/虚拟网卡运行和已批准的防火墙规则。不得要求候选地址或抓包。
- **Relay**：核对受控 Relay 健康、路径状态和配额类别；有可用 direct 时可提示重试，但不能保证路径。恢复 Relay 由 Relay 负责人执行。
- **目标机 RDP**：用户/目标机管理员在 Windows 设置中启用远程桌面，确认 Remote Desktop 服务运行、授权用户允许登录，并只启用批准的 RDP 防火墙规则；然后重跑本地诊断。

### 7.3 恢复条件

同时满足以下条件才可宣布恢复：

- 用原 account/device 和同等范围重新核验，最早失败层已变为 ok，或 RDP 层从 unreachable 变为 reachable。
- 至少完成一次用户侧重试；没有真实设备环境时只能写“本地 fake 验证通过”，不能写“用户已恢复”。
- P1/P2 由事故指挥确认没有新增同签名工单并完成观察窗；P3 由工单 owner 得到用户确认或记录无法联系后的关闭规则。
- 记录恢复时间、验证者、验证层和仍未知项，不记录内容。

### 7.4 回滚边界

- 若为启用 RDP/防火墙的临时验证，测试后由目标机管理员按其安全基线决定保留或撤销；撤销只回退本次特定设置，不能关闭整个主机防火墙。
- 若为服务版本/配置变更，使用对应发布 runbook 的 last-known-good/受控 rollout；本手册不增加远程命令或旁路回滚能力。
- 若缓解引发更大影响，立即停止继续变更、保留最小审计元数据并由事故指挥决定回滚。
- 删除操作不可由工单“回滚”；误删需停止后续删除并按既有受控备份恢复流程处理。

## 8. 复盘

P0/P1 必须复盘，P2 默认复盘，重复出现的 P3（30 天内同 code 三次及以上）做轻量复盘。复盘至少包含：

- 实际时间线、发现方式、级别变化、影响范围和最终失败层。
- 哪些受控证据支持/反驳了每一层；明确区分事实、推断和未知。
- 为什么现有保护没有更早发现/阻止，交接和沟通是否及时。
- 缓解、恢复、回滚是否有效；是否出现内容/凭据误采集。
- 有 owner 和截止日期的改进项。本文不授权顺势建设新监控、工单或远控功能，新增能力必须另立需求。
- 数据保留/删除计划和完成证明。

不得在复盘中粘贴原始流量、屏幕、文件、剪贴板、密码、token、私钥或候选/远端地址。

## 9. 审计、保留与删除

### 9.1 必须审计的动作

工单记录操作人、角色、时间、组织/查询授权、account/device 查询条件（受控系统内）、UTC 范围、查询原因、脚本 schema/classification、级别变化、每次交接、缓解/回滚批准人、恢复确认和删除完成时间。脚本本身不向中央系统写审计，因此运行者必须在工单中记录这些动作。

不要把本地绝对路径、原始输入、完整输出或完整 ID 复制到公共聊天。需要在受控工单中引用报告时使用 `account_ref`/`device_ref` 和 classification code。

### 9.2 默认保留上限

- 本地脚本输入/输出属于临时排障文件：工单关闭后 7 天内删除，且自生成起最长不超过 30 天，以较早者为准。
- 工单中的最小决策记录默认保留 90 天；合同、地区法规或组织政策要求更短时按更短期限。
- 产品审计/连接元数据继续遵循现有套餐/组织保留期。客服不得复制数据来延长可查询期限，也不得直接清理生产审计。
- P0/P1 需要 legal hold 或更长保留时，只能由安全/隐私负责人书面批准，记录范围、理由、到期日和解除人；解除后立即回到删除流程。

### 9.3 删除流程

1. 工单 owner 在关闭时列出本地输入、输出和临时副本所在受控位置，不记录文件内容。
2. 确认无活动安全 hold、审计或恢复需求；不确定时交隐私/安全负责人，不自行延长。
3. 删除本地输入/输出和重复副本；不要通过脚本清理产品审计或其他组织数据。
4. 在工单记录删除人、UTC 时间、文件类型和“已无已知副本”；不粘贴路径中的个人信息。
5. 发现误采集内容/凭据时，停止查看和传播，限制访问，立即升级安全/隐私响应，由其决定安全删除和通知。

## 10. 何时停止普通排查

任一条件成立，立即停止当前流程并按指定方向升级：

- suspected/confirmed 安全状态、跨组织结果、越权访问、账号/设备归属冲突。
- 工单或附件出现密码、token、私钥、屏幕、文件、剪贴板、候选地址或原始流量；不要继续打开/复制。
- 用户要求客服远程控制设备、查看内容、关闭整机安全控制或绕过 RBAC/额度。
- 证据显示正在进行的攻击、凭据泄露、内容暴露或审计篡改：升级安全负责人/事故指挥，至少 P1；确认暴露时按 P0。
- 一轮固定诊断仍全部 unknown、证据冲突，或 L1/L2 达到 30/60 分钟交接阈值。
- 同一受控失败 code 在同一时间窗口出现 3 个及以上独立工单：停止按单机问题处理，由 L2 评估 P2/P1 服务事件。
- 所需证据已超出现有保留期或当前角色无权查询：记录限制并交授权人员，不能通过收集用户内容补足。
